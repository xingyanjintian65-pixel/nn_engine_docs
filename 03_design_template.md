## 1. 設計方針

- **目的：** 常駐型のファイル検索・参照機能の基盤を作る。今回は常駐プロセスは作らず、関数呼び出しで実行する（REQ §1, §8）。
- **背景：** 独自AIツールの基幹機能・補助機能にすることと、Rust の学習を目的とする（REQ §1.2）。
- **機能構成：** `ls`（メタ情報）、`cat`（中身の取得）、`grep`（中身の検索）に相当する機能を**それぞれ独立した関数**として作る（FR-01〜FR-06）。
- **呼び出し方：** **ライブラリクレート（lib crate）**として作り、常駐プロセスやブラウザ連携から呼び出す API を用意する（NFR-04）。
- **エラー処理：** panic させない。エラーは `Result` で呼び出し元に返す（NFR-03, REQ §7.3）。
- **メモリ：** ファイルは**ストリームで読み込み**、内容を全部メモリに載せない。上限は 100MB（NFR-02, REQ §6）。
- **対応OS：** Windows / Ubuntu / macOS。OSに依存する処理は `std::path` と OS ごとの設定ディレクトリ取得に限る（NFR-06）。
- **関数の分け方：** 最小の機能ごとに関数を分ける。ただし**1つ〜3つ程度の関数からしか使わない処理は分けず**、使う側の関数の中に書く（NFR-05）。

### 1.1 スコープ

| 対象とするもの                   | 対象外とするもの             |
| ------------------------- | -------------------- |
| ファイル検索の基本機能（FR-01〜FR-06）  | 常駐機能                 |
| 検索結果の整形機能                 | 見た目を整えたブラウザ表示機能      |
| ブラウザ機能との連携機能（連携用データ形式の出力） | 行番号の出力（FR-07：不要）     |
| 設定ファイル（YAML）の生成と読み込み      | ファイル変更の検知（常駐化のときに追加） |
| インデックス・キャッシュ              |                      |

## 2. 全体構成

```
file_search/
├── Cargo.toml
├── src/
│   ├── lib.rs        # 公開APIの再エクスポート
│   ├── api.rs        # 外部（常駐プロセス・ブラウザ連携）からの呼び出し口
│   ├── config.rs     # 設定の定義、YAMLの読み書き
│   ├── scope.rs      # 検索範囲の定義と走査
│   ├── meta.rs       # ls 相当：存在確認・一覧取得・パターンでの絞り込み・属性取得
│   ├── content.rs    # cat 相当：バイナリ判定・文字コード判定・ストリーム読み込み
│   ├── search.rs     # grep 相当：中身の検索
│   ├── format.rs     # 検索結果の整形（テキスト / JSON）
│   ├── index.rs      # インデックス・キャッシュ
│   └── error.rs      # エラー型
└── tests/            # 結合テスト・性能テスト
```

> **実装との違い（2026-11-16）：** 実際は独立したパッケージ `file_search/` を作らず、`workdir` パッケージの `src/` に同じ名前のモジュールを置いている。テスト用の `TestDir` は `src/test_util.rs` と `tests/common/mod.rs` にある。処理本体はまだ `todo!()` のままである（IMP-FS-001 を参照）。

### 2.1 モジュールの依存関係

```
api ──┬─> config
      ├─> meta ──> scope
      ├─> content
      ├─> search ──> scope, content
      ├─> format
      └─> index ──> meta, config
（error は全モジュールから参照する）
```

- 依存は上から下への一方向とし、循環させない。
- `api` 以外のモジュールは互いを呼び出さず、組み合わせは `api` で行う。ただし `search` は走査（`scope`）と読み込み（`content`）を使う。

| 文字コードを変換しながらのストリーム読み込み | `encoding_rs_io` | 0.1.8 | content, search | REQ §6 読み込み方法 |
| シリアライズ | `serde`（`derive`） | 1.0 | 全体 | REQ §7 |
| 設定ファイル（YAML） | `noyalib` | 0.0.28 | config | REQ §7 設定 |
| JSON 出力・インデックスの保存 | `serde_json` | 1.0 | format, index | ブラウザ連携、REQ §8 |

> **実装との違い（2026-11-16）：** 実際の Cargo.toml では `noyalib` が 0.0.60、`chrono` は `serde` feature なしになっている。詳しくは CRATE-FS-001 v0.5 §6 を参照。

**標準ライブラリで実装するもの（外部クレートを使わない）**
| 用途 | 実装方法 | 関連する章 |
|---|---|---|
| 存在の確認・属性の取得 | `Path::try_exists`, `fs::metadata` | §4.1, §4.4 |
| エラー型 | `std::fmt::Display`, `std::error::Error`, `From` を自分で実装する（`thiserror` は使わない） | §3.8 |
| テスト用の一時ディレクトリ | `std::env::temp_dir()` と、`Drop` で削除する補助の型（`tempfile` は使わない） | §9 |

**保留・今回は使わない**
| クレート | 状態 | 理由 |
|---|---|---|
| `tokio-stream` 0.1.19 | 保留 | 同期処理と非同期処理のどちらで作るか未決（§11 D-05） |
| `tantivy` 0.27.0, `lindera` 6.2.0 | 保留 | インデックスで全文検索を行うか未決（§11 D-06） |
| `notify` 8.2.2 | 今回は使わない | 常駐化するときにファイル変更の検知で使う（§8） |

> この設計書は**同期処理**で作る前提とする。`encoding_rs_io` が同期処理（`std::io::Read`）にだけ対応しているため。

## 3. データ構造

### 3.1 設定 `Config`（YAMLファイルと1対1で対応）

| フィールド           | 型               | 既定値                      | 説明                | 要件           |
| --------------- | --------------- | ------------------------ | ----------------- | ------------ |
| root            | `PathBuf`       | 実行環境のルート（`/` または `C:\`）  | 走査の起点             | §3 ルートディレクトリ |
| max_depth       | `Option<usize>` | `None`（制限なし）             | 再帰の深さ             | §3 再帰の深さ     |
| exclude         | `Vec<String>`   | 空                        | 除外する glob パターン    | §3 除外条件      |
| follow_symlinks | `bool`          | `true`                   | シンボリックリンクをたどるか    | §3 シンボリックリンク |
| encodings       | `Vec<String>`   | `["UTF-8", "Shift_JIS"]` | 文字コードを判定するときに試す順番 | §6 文字コード     |
| max_memory_mb   | `u64`           | `100`                    | メモリ使用量の目安         | NFR-02       |
| read_buffer_kb  | `usize`         | `64`                     | ストリーム読み込みのバッファサイズ | §6 読み込み方法    |
| index_enabled   | `bool`          | `true`                   | インデックスを使うか        | §8 インデックス    |

**YAMLの例**

```yaml
root: /home/user/projects
max_depth: 10
exclude:
  - "**/.git/**"
  - "**/target/**"
follow_symlinks: true
encodings: [UTF-8, Shift_JIS]
max_memory_mb: 100
read_buffer_kb: 64
index_enabled: true
```

**読み書きの実装（`noyalib`）**

- `Config` に `#[derive(Serialize, Deserialize)]` と `#[serde(default)]` を付け、YAML に書かれていない項目には既定値（`Default` の実装）を使う（C-09-03）。
- 読み込みは `noyalib::from_str`、書き込みは `noyalib::to_string` を使う。

**保存先**（`dirs::config_dir()` で取得する）
| OS | 設定ファイル |
|---|---|
| Linux | `~/.config/file_search/config.yaml` |
| macOS | `~/Library/Application Support/file_search/config.yaml` |
| Windows | `%APPDATA%\file_search\config.yaml` |

※ インデックスファイルは設定ファイルと同じディレクトリに置く（REQ §8）。

### 3.2 検索範囲 `SearchScope`

`Config` から作る。呼び出すときに一部の項目だけ上書きすることもできる。

| フィールド           | 型               | 説明                              |
| --------------- | --------------- | ------------------------------- |
| root            | `PathBuf`       | 起点（ユーザーが指定。未指定なら `Config.root`） |
| max_depth       | `Option<usize>` |                                 |
| exclude         | `GlobSet`       | コンパイル済みの除外パターン                  |
| follow_symlinks | `bool`          |                                 |

### 3.3 ファイル情報 `FileInfo`

| フィールド      | 型                    | 説明                                  | 要件          |
| ---------- | -------------------- | ----------------------------------- | ----------- |
| path       | `PathBuf`            | ファイルパス                              | FR-02       |
| exists     | `bool`               | 存在するか                               | FR-01       |
| is_text    | `bool`               | 人が読めるファイルか（バイナリなら `false`）          | §3 対象ファイル種別 |
| size       | `u64`                | サイズ（バイト）                            | FR-04       |
| modified   | `Option<SystemTime>` | 更新日時                                | FR-04       |
| created    | `Option<SystemTime>` | 作成日時（OS・ファイルシステムが対応していない場合は `None`） | FR-04, 用語定義 |
| is_symlink | `bool`               | シンボリックリンクか                          | §3          |

### 3.4 検索条件 `Query`

| フィールド         | 型             | 説明                                                               |
| ------------- | ------------- | ---------------------------------------------------------------- |
| pattern       | `String`      | 検索したい文字列（REQ §7.1 任意文字列）                                         |
| is_regex      | `bool`        | `true` なら正規表現として扱う。`false` なら文字列として扱う（内部ではエスケープして `Regex` に変換する） |
| ignore_case   | `bool`        | 大文字と小文字を区別しない                                                    |
| name_patterns | `Vec<String>` | 対象にするファイル名の glob（FR-03）                                          |

### 3.5 検索結果 `SearchResult`

| フィールド       | 型                   | 説明                  |
| ----------- | ------------------- | ------------------- |
| matches     | `Vec<FileMatch>`    | 条件に一致したファイルごとの結果    |
| file_count  | `usize`             | 一致したファイルの件数         |
| match_count | `usize`             | 一致した行の総数            |
| skipped     | `Vec<SkippedEntry>` | 読み込めずにスキップしたファイルの一覧 |

`FileMatch`
| フィールド | 型 | 説明 |
|---|---|---|
| path | `PathBuf` | ファイルパス |
| lines | `Vec<String>` | 一致した行の内容（行番号は持たない：FR-07 不要） |

> 要件定義の出力欄にある件数の型 `i128` は、件数が負の値にならないため Rust で一般的な `usize` で表す。

### 3.6 一覧取得の結果 `ListResult`

| フィールド   | 型                   | 説明             |
| ------- | ------------------- | -------------- |
| files   | `Vec<PathBuf>`      | 条件に一致したファイルのパス |
| count   | `usize`             | 件数             |
| skipped | `Vec<SkippedEntry>` | 走査できなかったパス     |

### 3.7 スキップ記録 `SkippedEntry`

| フィールド  | 型            | 説明                                                                            |
| ------ | ------------ | ----------------------------------------------------------------------------- |
| path   | `PathBuf`    |                                                                               |
| reason | `SkipReason` | `PermissionDenied` / `Binary` / `DecodeFailed` / `Io(String)` / `SymlinkLoop` |

### 3.8 エラー型 `FsError`（標準ライブラリで定義）

`thiserror` は使わず、次のものを自分で実装する。

- `std::fmt::Display`：エラーメッセージ（日本語）
- `std::error::Error`：`Io` の場合は `source()` で元のエラーを返す
- `From<std::io::Error>`：`?` 演算子で変換できるようにする。`ErrorKind::NotFound` は `NotFound`、`ErrorKind::PermissionDenied` は `PermissionDenied` に変換する
- `From<regex::Error>`, `From<globset::Error>`：`InvalidPattern` に変換する
- `From<noyalib` のエラー型`>`：`Config` に変換する

| バリアント                       | 発生する状況                                                      | 要件           |
| --------------------------- | ----------------------------------------------------------- | ------------ |
| `NotFound(PathBuf)`         | 指定したパスが存在しない                                                | §7.3         |
| `PermissionDenied(PathBuf)` | 指定したパスへのアクセス権限がない                                           | §7.3, §6     |
| `NotText(PathBuf)`          | バイナリファイルの中身を取得しようとした                                        | §6 バイナリ      |
| `Decode(PathBuf)`           | 対応する文字コードで読めない                                              | §6 文字コード     |
| `InvalidPattern(String)`    | glob や正規表現の書き方が正しくない                                        | FR-03, FR-06 |
| `Config(String)`            | 設定ファイルの読み書き・解析に失敗した。`dirs::config_dir()` が設定ディレクトリを取得できなかった | §7 設定、NFR-06 |
| `Io(std::io::Error)`        | 上記以外の入出力エラー                                                 | §7.3         |

## 4. 関数仕様

> 「条件ID」は実装記録（IMP-FS-001）の網羅確認表で使う。
> 公開するかどうか：**pub** は `api` から外部に公開する関数、**crate** はクレート内だけで使う関数。

### 4.1 `exists`（meta.rs）

| 項目       | 内容                                                    |
| -------- | ----------------------------------------------------- |
| 対応する要件ID | FR-01                                                 |
| シグネチャ    | `pub fn exists(path: &Path) -> Result<bool, FsError>` |
| 概要       | 指定したパスが存在するか判定する。バイナリファイルも判定できる                       |
| 入力       | 判定したいパス                                               |
| 出力       | 存在すれば `true`、しなければ `false`                            |
| エラー      | 権限がなく判定できない場合は `PermissionDenied`                     |
| 再利用の想定   | 常駐化したときの監視対象の確認、インデックスの有効性確認                          |

| 条件ID    | 条件                                              |
| ------- | ----------------------------------------------- |
| C-01-01 | 存在するファイル・ディレクトリに対して `Ok(true)` を返す              |
| C-01-02 | 存在しないパスに対して `Ok(false)` を返す（エラーにしない）            |
| C-01-03 | バイナリファイルでも存在を判定できる                              |
| C-01-04 | 権限エラーのときは `Err(PermissionDenied)` を返し、panic しない |

### 4.2 `walk`（scope.rs）

| 項目       | 内容                                                                                           |
| -------- | -------------------------------------------------------------------------------------------- |
| 対応する要件ID | FR-02、§3 検索範囲                                                                                |
| シグネチャ    | `pub(crate) fn walk(scope: &SearchScope) -> Result<impl Iterator<Item = WalkItem>, FsError>` |
| 概要       | 検索範囲の中を再帰的に走査し、ファイルを1件ずつ返す。全件をメモリに溜めないようイテレータで返す                                             |
| 使うクレート   | `walkdir`（`max_depth`, `follow_links`, `filter_entry`）、`globset`（除外条件）                       |
| 入力       | 検索範囲                                                                                         |
| 出力       | `WalkItem`（ファイルパス、またはスキップ記録）                                                                 |
| エラー      | 起点のパスが存在しない、または権限がない場合は `Err` を返す。走査の途中で起きたエラーは `SkippedEntry` として返し、走査を続ける                  |
| 再利用の想定   | `list_files`、`search_content`、`build_index` から使う                                             |

| 条件ID    | 条件                                                  |
| ------- | --------------------------------------------------- |
| C-02-01 | `max_depth` で指定した深さより下は走査しない                        |
| C-02-02 | `exclude` に一致するパスは走査しない（ディレクトリが一致した場合は中も走査しない）      |
| C-02-03 | `follow_symlinks = true` のときシンボリックリンクをたどる           |
| C-02-04 | シンボリックリンクがループしていても無限ループにならず、`SymlinkLoop` としてスキップする |
| C-02-05 | 途中のディレクトリで権限エラーが起きてもスキップして走査を続ける                    |
| C-02-06 | 起点が存在しない、または権限がない場合は `Err` を返す                      |

### 4.3 `list_files`（meta.rs）

| 項目       | 内容                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------- |
| 対応する要件ID | FR-02, FR-03                                                                                      |
| シグネチャ    | `pub fn list_files(scope: &SearchScope, name_patterns: &[String]) -> Result<ListResult, FsError>` |
| 概要       | 検索範囲の中のファイルパスを一覧で取得する。`name_patterns` を指定した場合は、ファイル名が一致するものだけにする                                  |
| 使うクレート   | `globset`（`GlobSetBuilder` で複数のパターンをまとめてコンパイルする）                                                  |
| 入力       | 検索範囲、ファイル名の glob（空なら全件）                                                                           |
| 出力       | `ListResult`（パス・件数・スキップ一覧）                                                                        |
| エラー      | `walk` のエラー、glob が正しくない場合は `InvalidPattern`                                                       |
| 再利用の想定   | 常駐化したときの定期走査、インデックスの作成                                                                            |

| 条件ID    | 条件                                            |
| ------- | --------------------------------------------- |
| C-03-01 | 検索範囲の中のファイルパスをすべて返す                           |
| C-03-02 | `name_patterns` に一致するファイルだけを返す                |
| C-03-03 | バイナリファイルも一覧には含める（存在確認は可能という要件のため）             |
| C-03-04 | `count` が `files` の件数と一致する                    |
| C-03-05 | 書き方が正しくない glob に対して `Err(InvalidPattern)` を返す |

> FR-03（パターンでの絞り込み）は `list_files` と `search_content` の2か所でしか使わないため、NFR-05 の方針に従い独立した関数にせず、それぞれの関数の中で `GlobSet` を使う。

### 4.4 `get_metadata`（meta.rs）

| 項目       | 内容                                                              |
| -------- | --------------------------------------------------------------- |
| 対応する要件ID | FR-04                                                           |
| シグネチャ    | `pub fn get_metadata(path: &Path) -> Result<FileInfo, FsError>` |
| 概要       | サイズ・更新日時・作成日時などの属性を取得する                                         |
| 入力       | ファイルパス                                                          |
| 出力       | `FileInfo`                                                      |
| エラー      | `NotFound`, `PermissionDenied`, `Io`                            |
| 再利用の想定   | インデックスの作成、検索結果の整形                                               |

### 4.5 `is_text_file`（content.rs）

| 項目         | 内容                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 対応する要件ID   | §3 対象ファイル種別、§6 バイナリ                                                                                              |
| シグネチャ      | `pub fn is_text_file(path: &Path) -> Result<bool, FsError>`                                                      |
| 概要         | 人が読めるファイルかどうかを判定する                                                                                               |
| 判定方法       | 先頭 8KB を読み、NULバイト（`0x00`）があればバイナリとする（`grep` と同じ考え方）。そのうえで、設定した文字コードのどれかで読めればテキストとする                              |
| 使うクレート     | `encoding_rs`（`UTF_8` / `SHIFT_JIS` の `decode_without_bom_handling_and_without_replacement` で、変換できない文字がないか確認する）  |
| 文字コードの判定結果 | 判定に使った文字コード（`&'static Encoding`）も返せるようにし、`read_content`・`search_content` で再利用する（内部用の関数 `detect_encoding` として分ける） |
| 再利用の想定     | `get_metadata`、`read_content`、`search_content` の3か所から使い、常駐化したときも使うため独立させる                                        |

| 条件ID    | 条件                                |
| ------- | --------------------------------- |
| C-05-01 | UTF-8 のテキストファイルを `true` と判定する     |
| C-05-02 | Shift_JIS のテキストファイルを `true` と判定する |
| C-05-03 | 画像・実行ファイルなどのバイナリを `false` と判定する   |
| C-05-04 | 空ファイルを `true` と判定する               |

### 4.6 `read_content`（content.rs）

| 項目       | 内容                                                                                                                         |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 対応する要件ID | FR-05、§6 読み込み方法・文字コード                                                                                                      |
| シグネチャ    | `pub fn read_content<W: Write>(path: &Path, config: &Config, out: &mut W) -> Result<(), FsError>`                          |
| 概要       | ファイルの中身を UTF-8 に変換し、ストリームで `out` に書き出す（`cat` 相当）。全部をメモリに読み込まない                                                             |
| 文字コードの判定 | 先頭のバッファで `config.encodings` の順に試し、最初に読めた文字コードでファイル全体を変換する                                                                  |
| 使うクレート   | `encoding_rs_io`（`DecodeReaderBytesBuilder::new().encoding(Some(判定した文字コード))` で、UTF-8 に変換しながら読む `Read` を作り、`BufReader` で包む） |
| 入力       | ファイルパス、設定、出力先                                                                                                              |
| 出力       | 書き出しが成功すれば `Ok(())`                                                                                                        |
| エラー      | `NotFound`, `PermissionDenied`, `NotText`（バイナリの場合）, `Decode`, `Io`                                                         |
| 再利用の想定   | ブラウザ連携でのファイル表示、AIツールへのファイル内容の受け渡し                                                                                          |

| 条件ID    | 条件                                                  |
| ------- | --------------------------------------------------- |
| C-06-01 | UTF-8 のファイルの中身をそのまま出力する                             |
| C-06-02 | Shift_JIS のファイルを UTF-8 に変換して出力する                    |
| C-06-03 | バイナリファイルには `Err(NotText)` を返す                       |
| C-06-04 | 100MB を超えるファイルを読んでも、メモリ使用量が `read_buffer_kb` 程度に収まる |
| C-06-05 | 存在しない・権限がないファイルには `Err` を返し、panic しない               |

> 呼び出し元で `String` が欲しい場合は、`out` に `Vec<u8>` を渡す。大きなファイルではメモリの上限を超えるおそれがあるため、`api` 側で `max_memory_mb` を超えるファイルは `String` で返さないようにする。

### 4.7 `search_content`（search.rs）

| 項目       | 内容                                                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 対応する要件ID | FR-06（FR-03 の絞り込みを含む）                                                                                                                            |
| シグネチャ    | `pub fn search_content(scope: &SearchScope, query: &Query, config: &Config) -> Result<SearchResult, FsError>`                                    |
| 概要       | 検索範囲のテキストファイルを1行ずつストリームで読み、文字列・正規表現に一致した行を集める（`grep` 相当）                                                                                         |

| 再利用の想定   | AIツールからの全文検索                                                                                                                                     |

| 条件ID    | 条件                                               |
| ------- | ------------------------------------------------ |
| C-07-01 | 文字列（`is_regex = false`）に一致する行を返す。記号は正規表現として解釈しない |
| C-07-02 | 正規表現（`is_regex = true`）に一致する行を返す                 |

| C-07-06 | 読めないファイルがあってもスキップして最後まで処理し、`skipped` に記録する       |
| C-07-07 | `file_count` と `match_count` が実際の件数と一致する         |
| C-07-08 | 行番号は出力しない（FR-07 不要）                              |

### 4.11 公開API `Searcher`（api.rs）

    pub fn new(config_path: Option<&Path>) -> Result<Self, FsError>;   // 設定とインデックスを読み込む

## 5. 処理の流れ

### 5.1 文字列検索（代表的な使い方）

```
呼び出し元
  └─ Searcher::new()          … 設定（YAML）とインデックスを読み込む
  └─ Searcher::search(root, query)
        ├─ SearchScope を作る（root の指定がなければ Config.root）
        ├─ glob・正規表現をコンパイル（失敗したら Err(InvalidPattern)）
        ├─ walk() で走査（インデックスが有効ならインデックスのパス一覧を使う）
        │    └─ 途中のエラーは skipped に記録して続ける
        ├─ name_patterns で絞り込む
        ├─ is_text_file() でバイナリを除外 → skipped(Binary)
        ├─ 文字コードを変換しながら1行ずつ照合
        │    └─ 読み込みエラーは skipped に記録して続ける
        └─ SearchResult を返す
  └─ format_result(result, Json)  … ブラウザ連携に渡す
```

### 5.2 設定の更新

```
呼び出し元（ブラウザ連携など）
  └─ Searcher::update_config(config)
        ├─ save_config() で YAML に保存
        └─ 検索範囲が変わった場合はインデックスを無効にする
```

## 6. エラー処理の方針

| 状況                 | 動作                                                             | 要件       |
| ------------------ | -------------------------------------------------------------- | -------- |
| 指定したパスが存在しない       | `Err(NotFound)` で呼び出し元に返す                                      | §7.3     |
| 指定したパスに権限がない       | `Err(PermissionDenied)` で呼び出し元に返す。Linux 系では `sudo` で実行すれば走査できる | §7.3, §6 |
| 走査・検索の途中のファイルが読めない | `skipped` にまとめてスキップし、最後に結果と一緒に返す                               | §7.3     |
| バイナリファイル           | 存在の確認と一覧への表示はできる。中身の取得・検索は行わない                                 | §6       |
| 全体                 | `unwrap()` / `expect()` / 範囲外のインデックスアクセスは使わない。`?` 演算子でエラーを返す   | NFR-03   |

> 「指定したパス」は呼び出し元が明示したパス（検索の起点、`read` の対象）を指す。走査中に見つかったファイルのエラーは処理全体を止めないため、`skipped` に記録する。

### 9.1 テスト用の一時ディレクトリ `TestDir`

`tempfile` を使わないため、テスト用の補助の型を作る。

```rust
#[cfg(test)]
pub(crate) struct TestDir { path: PathBuf }

#[cfg(test)]
impl TestDir {
    /// std::env::temp_dir() の下に、テスト名とプロセスID・時刻を付けたディレクトリを作る
    pub fn new(name: &str) -> std::io::Result<Self>;
    pub fn path(&self) -> &Path;
}

#[cfg(test)]
impl Drop for TestDir {
    /// テストが失敗して panic した場合も含め、ディレクトリを削除する（削除の失敗は無視する）
    fn drop(&mut self);
}
```

- テストは並列で実行されるため、ディレクトリ名が重ならないようにする。
- 補助の型なので、単体テストと結合テストの両方から使えるよう `tests/common/mod.rs` にも同じものを置く。
